## 尚未验证或不能保证的项目

- 除上述已测动作外，静音、其他输入与媒体按钮虽已抓到真实编码，未逐项确认最终音箱效果。
- 新一套同型号、其他遥控硬件修订、随机 BLE 地址、其他 JBL 产品、其他 ESP32 板卡与 Flash 容量。
- 参数化发布固件在新设备上的完整配对、实物控制和重启恢复；本次归档不自动刷写原在线设备。
- 整套设备断电再上电、长时间稳定性、极端距离／干扰和并发压力。
- 厂商 ID 30 大报告、双链 MTU、通用输出报告转发或多音箱／多遥控路由。
- 未发送、长按过滤、队列拥塞、松开报告拒绝等分支的完整硬件故障注入。已有源码／编译检查不等于这些现场测试完成。
- 本项目不通过蓝牙读回音箱电源、当前输入、音量或静音状态。另有网络只读音量观察，未据此实现或验证网络写控制。
- HA 离线记录补传、完整发送审计、历史永久保存，以及公开演示二进制在真实网络上直接运行。

## 同型号复用时必须重新确认

1. 原遥控器和主音箱两个 **public BLE MAC**；两端分别写入私密配置。音箱是 BLE central，其地址不能靠 Wi-Fi MAC 或普通设备扫描猜测；未知时须通过连接建立监听或可靠端点记录确认身份与 public 类型。不能只改 Wi-Fi 就刷机。
2. ESP32 的实际型号、Flash 容量、唯一目标端口及 ESPHome 2026.9.1／IDF 5.5.5。
3. 新遥控器的 HID Report Reference／实际报告长度是否与已捕获协议一致。中继会发现 Report Reference，仍不代表任意 HID 协议兼容。
4. 两端分别与 ESP32 配对，以及光纤→USB、音量和待机／唤醒的实物验证。
5. 新 HA 实例实际生成的实体 ID。仓库按钮名、固件实体键与既有 HA 实体 ID 不能混用。
6. 发布 manifest 和 SHA256SUMS；真实部署须重新编译本机参数。演示 factory／OTA 文件不包含可直接复用的网络和设备身份配置。

Nordic 等工具可能用于首次地址确认，但在两端 MAC 已知后的正常部署与日常控制中不需要。地址已知也不等于新套设备的协议与实物行为已经验证。

## 升级规则

不要自动升级 ESPHome 或 ESP-IDF，也不要借版本升级自动刷在线设备。升级需要重新检查本地 BLE 组件与生成接口、运行协议／来源检查、完成编译，并在明确的目标设备上重做配对与恢复验证。保持现有绑定是正常升级前提；清空 NVS、重建分区和批量删除绑定不属于常规部署步骤。
