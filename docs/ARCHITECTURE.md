## 数据流与角色

```text
原装遥控器（BLE peripheral / GATT server）
  │ 加密连接、HID 输入通知
  ▼
ESP32-C3：BLE client 读取原遥控器
  │ jbl_remote_relay 原始报告转发
  ▼
ESP32-C3：BLE peripheral / HID GATT server
  │ 输入通知
  ▼
主音箱（BLE central / GATT client）

HA 原生按钮 → 加密 ESPHome API → send_key → 同一 HID server → 音箱
原遥控接收 / HA 发送结果 → 独立 event + text_sensor → HA 活动卡
```

一块 ESP32 同时承担两种 BLE 角色。配置允许两条连接，服务端只接受一台音箱。两个目标的 public MAC 分别由私密参数提供；音箱地址也必须明确配置，不是扫描后自动学习。它不是通用 HID 路由器或多音箱网关。

音箱处于 central 角色，因此普通广播扫描不保证暴露它在这条连接中的身份。其 BLE MAC 不能从 Wi-Fi MAC 推算；未知地址须通过原连接建立监听或可信端点记录确认，并验证 public 地址类型。Nordic 可用于这一首次身份研究；地址已知后的正常部署与日常控制不依赖它。

## HID 报告与按键

主服务为 HID `0x1812`。报告特征 UUID 都是 `0x2A4D`，不能仅凭 UUID 区分。中继读取实际 `0x2908` Report Reference，发现输入 ID **1、3、30** 及其 CCCD，再逐一完成订阅；抓包中的 ATT handle 只是当时证据，不应当作另一台设备的固定地址。

- ID 1：8 字节，承载大部分按键。
- ID 3：实测按键通知为 **2 字节**；原 Report Map 虽声明 4 字节，复现必须保留实测的 2 字节。
- ID 30：保留厂商输入通道；大包与双链 MTU 行为尚未实机验证。

13 个按键名称来自人类按实际遥控器的受控序列与抓包对应关系，不是按标准 HID usage 名称猜测。服务复现还保留 ID 1／30 输出 Report Reference，但不提供通用输出报告转发。

## 原遥控与 HA 共存

原遥控器认证和三通道订阅完成后才进入就绪状态。转发保留原始按下、重复及释放报告；观察器只在新的有效按下时发布接收事件，因此长按重复报文不会刷满历史。松开后再按同一个键仍会产生新事件。

HA 按键通过 `jbl_send_key` 队列处理，最多 10 次运行；中继提交按下后安排约 **150 ms** 的合成释放，脚本间隔 **160 ms**。原遥控器占用对应报告通道时，冲突的 HA 请求被拒绝；新的物理报告可取消待发的 HA 合成释放，避免把用户仍按住的键错误释放。离线按键不会作为待重连命令排队重放。

## 事件语义

| 实体 | 含义 | 不应据此推断 |
| --- | --- | --- |
| 原装遥控器连接 | 目标遥控器已认证，三个输入通道订阅完成 | 音箱一定收到／执行 |
| 音箱蓝牙连接 | ESP32 服务端存在音箱连接 | 音箱已开机、指定输入或音量 |
| 原遥控按键接收事件 | ESP32 收到可观察的原遥控按键；中文 `event_type` | 音箱执行确认 |
| HA 按键发送事件：已提交 | 本地 BLE 协议栈接受按下报告 | 无线送达、音箱执行或释放必定成功 |
| HA 按键发送事件：未发送 | 进入处理后的请求被拒绝 | 所有网络／队列丢失均有记录 |

原遥控与 HA 发送分别使用 `event` 和最近文字实体。HA 发送不会伪造原遥控接收事件；释放失败写日志，不制造第二个按下事件。固件重启会把最近文字重置为“本次启动尚未收到／发送”，不因此产生事件。

HA 原生事件的状态是接收时间，类型在 `event_type`。重复同键也有新时间，自动化应依据事件而非仅比较最近文字。HA 记录依赖实际在线状态和 Recorder 设置，没有离线补传；旧英文历史不会因新事件使用中文而被回写。

## 绑定与恢复

BLE 绑定保存在设备存储中；音箱的目标订阅状态由服务端补充保存并在目标认证后恢复。普通固件更新应保留现有分区、凭据和绑定。原套硬件已验证 ESP32 重启后恢复音箱连接和订阅；原遥控器第一次按键可能只触发唤醒重连。

两个维护入口按目标分别处理：音箱维护处理音箱绑定及其订阅；原遥控器维护处理原遥控器绑定。它们不是普通重连按钮，不应改成清空所有 bond 或擦除 NVS。更换实体、协议或目标身份后，须重新核对这些持久化数据与新配置是否一致。

## HA 页面

“状态与控制”包含静态关系图、实时连接状态、最近收发、13 个控制按钮和两组 24 小时活动；“配对说明”独立放置两个维护操作。全部使用原生卡片。时间采用 `time_format: {type: time, style: long}` 显示秒。

固件中文显示名和 API 键的稳定性不保证新 HA 实例生成相同 `entity_id`。导入仪表盘前须读本实例实体注册结果并建立对应关系，不能机械复用原部署前缀。
